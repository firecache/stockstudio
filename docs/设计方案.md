# 股票 App 设计方案（Android / iOS / 鸿蒙）

> 参考项目：`jundizhou/easy-stock`、`hzy1522/tickflow-stock-panel`
> 界面参考：开盘啦（Kaipanla）
> 定位：移动端看盘/分析 App（首版不做交易下单）

---

## 1. 目标与范围

### 1.1 产品形态
- 三端一致体验：**Android / iOS / 鸿蒙（HarmonyOS NEXT）**
- 界面对标**开盘啦**：深色看盘、简洁、以「情绪周期 / 涨停复盘 / 题材梯队 / 资金流」为核心卖点（这正是开盘啦区别于同花顺/东财的差异点，也是 easy-stock 明确对标并抓取数据的产品）
- 纯看盘 + 分析，不做实盘交易（避开券商资质与资金安全）

### 1.2 数据需求（硬指标）
| 数据 | 周期 | 范围 | 用途 |
|---|---|---|---|
| 每日行情 | 日 K（OHLCV + 成交额 + 换手 + 复权因子） | 2010 至今 · 全市场 | K 线、均线、指标 |
| 分钟行情 | 1 / 5 / 15 / 30 / 60 分钟 K | 2010 至今 | 分时缩放、周期 K 线、量价分析 |
| 分时 | 当日实时分时（约 240 点）+ 历史任意日分时 | 当日实时 + 历史 | 分时图、盘中异动 |
| 辅助 | 题材/概念、涨停池、连板、龙虎榜、资金流、公告、资讯 | 近实时 | 开盘啦式看盘功能 |

### 1.3 首版不做（明确排除）
- 实盘下单 / 模拟盘
- 量化回测 / 因子挖掘（tickflow 的核心能力，但与本产品无关）
- AI 荐股 / 涨停预测（监管红线，参考 tickflow 免责声明）

## 2. 参考项目分析：各借什么

### 2.1 easy-stock（AI 时代 A 股研究工作台）
**借：**
1. **多源数据聚合**——开盘啦、东方财富、新浪、财联社统一聚合，带「数据源 + 抓取时间 + 降级状态」的可追溯设计。这套「一个数据点知道来自哪、延迟多少、挂了怎么降级」的思路必须抄。
2. **领域模型**——趋势 / 题材 / 连板 / 情绪 / 量价 / 相对强度抽象成可计算模型。这是开盘啦式 App 的后端灵魂。
3. **情绪周期算法 + 涨停复盘闭环**——梯队、晋级率、昨日反馈、情绪历史，同一视图。

**不借：**
- 它是 Web 工作台 + 本地 Hermes Runtime 的「研究型」产品，不是移动端 C 端看盘 App；
- Agent 浏览器抓雪球/淘股吧/公众号——那是内容采集，不是行情管道。

### 2.2 tickflow-stock-panel（多市场量化工作台）
**借：**
1. **数据管道架构**——APScheduler 调度 + 数据源插件化（stock-sdk / YAML 自定义源）+ Polars 指标流水线（一次扫表落盘 enriched Parquet）。
2. **存储**——Parquet（列存）+ DuckDB（查询）+ 磁盘缓存按市场隔离。自托管、零运维，非常适合行情历史库。
3. **复权因子处理**——`adj_factor` 独立因子表、前/后复权自行计算（比直接用源前复权更可控、可审计）。
4. **市场注册表**——交易规则（涨跌幅、T+N、最小单位、印花税）单一事实源；即便首版只做 A 股，这层抽象留着做港美股扩展极省事。

**不借：**
- 选股引擎 / 回测 / 因子挖掘 / 监控中心——量化工作台功能，与本产品无关。

### 2.3 结论
> **后端 = tickflow 的数据管道与存储 + easy-stock 的多源聚合与情绪/题材领域模型；前端 = 全新移动端，交互对标开盘啦。**

## 3. 关键技术难点（必须先说清）

### 3.1 数据获取是第一难点（也是成本/合规的源头）

| 数据类型 | 免费源 | 2010 至今覆盖 | 说明 |
|---|---|---|---|
| 日 K（含复权因子） | 东财 / 腾讯 / 新浪 / baostock | ✅ 全量 | 无难度 |
| 5/15/30/60 分钟 K | **baostock**（免费、需登录）/ 东财 | ✅ 基本可回填到 2006+ | baostock 无 1 分钟数据，且逐股逐日拉取，全市场首次回填耗时数天 |
| 1 分钟 K | 东财（仅近端几年） | ❌ 只有近几年 | **2010 至今的 1 分钟必须付费**（TickFlow / 聚宽 / 米筐 / 开盘啦 / Wind） |
| 分时（当日） | 腾讯 `qt.gtimg.cn` / 东财 push2 | ✅ 实时免费 | 当日无难度 |
| 历史分时（复盘过去任意日） | 东财 `trends2`（仅最近数月） | ❌ 只保留近期 | **历史分时需付费，或改用「1 分钟 K 聚合出 240 点」自行构造** |
| 题材/概念/涨停/龙虎榜/资金流 | 东财 / 同花顺 / 开盘啦（部分需 token） | ⚠️ 实时可得，历史浅 | 开盘啦类深度数据部分接口需登录/token |

**核心判断：**
- **日线 + 5/15/30/60 分钟**：免费源（baostock 为主）可以做到 2010 至今全量回填。
- **1 分钟 + 任意历史分时**：免费源做不到 2010 至今。两条路：
  - （A）**自研降级方案**——1 分钟只用东财近端 + 历史分时用「5 分钟 K 插值」近似（够看盘，不够精确）；
  - （B）**付费数据源**——一次性购买或订阅 TickFlow（tickflow 项目同款）/ 聚宽 / 米筐，直接补齐 1 分钟与历史分时。

> 建议：**MVP 用免费源跑通全链路（日线 + 5/15/30/60 分钟全覆盖，1 分钟与历史分时降级为「近端真实 + 远端近似」），预留付费数据源插件接口**——这正是 tickflow 的「数据源插件化」能带来的收益，付费源以后插上即用。

### 3.2 合规风险（必须立项时确认）
1. **免费源商用风险**：东财/腾讯/新浪的行情接口 ToS 均禁止商用抓取。**学习研究/个人自用可用免费源；商业化上架必须购买数据授权**（腾讯行情、开盘啦、同花顺 iFinD、聚宽等均有商用授权）。
2. **监管红线**：不做荐股/交易信号/涨停预测；行情展示 + 客观统计（情绪周期、涨停复盘是客观数据整理）相对安全，但 AI 结论需加免责声明（参考 tickflow 的「不构成投资建议」）。
3. **上架**：iOS 需处理「金融类 App 资质」审核（行情展示一般可，交易/荐股需资质）；鸿蒙/安卓商店同理。

## 4. 技术选型

### 4.1 客户端（三端跨平台）

**主推：uni-app x（Vue3 + uts）**

| 维度 | uni-app x | Flutter | React Native | 原生三套 |
|---|---|---|---|---|
| 鸿蒙 NEXT 支持 | ✅ 官方强支持，5000+ 鸿蒙插件 | ⚠️ 社区桥接，落后主版本（3.22-ohos） | ⚠️ 社区适配，风险高 | ✅ 原生 ArkTS |
| 代码复用率 | ~95%，一套代码 + 小程序 | ~100% | 80-90% | 0（3 套） |
| 性能（冷启动/内存） | 原生渲染，接近原生（500-700ms） | 接近原生（800-1000ms） | 偏弱（1000-1200ms） | 最佳 |
| 学习/维护成本 | 低（Vue 生态 + HBuilderX） | 中（Dart） | 中（JS） | 高（3 团队） |
| 团队匹配 | PM + Vue 前端即可 | 需 Dart 经验 | 需 RN 经验 | 需 3 端工程师 |

选 uni-app x 的理由：**鸿蒙 NEXT 是官方维护、成案例最多、且能顺手出小程序/Web**；Vue 栈对 PM + 少量前端最友好；与现有 `hbuilderx-uniapp` 技能配套。

**图表库：klinecharts**（K 线/分时事实标准，作者 lihu，支持原生 JS/Vue/React/uni-app/小程序）
- K 线、分时、五日分时、技术指标（MA/EMA/MACD/KDJ/BOLL/VOL）、缩放拖拽十字光标开箱即用。
- 鸿蒙端渲染路径：**renderjs / web-view 承载 canvas**（成熟方案，多数行情 App 的 K 线本就是 webview 承载），后续可选 ArkUI canvas 原生重绘优化。
- 备选：Flutter + `k_chart`（klinecharts 的 Flutter 移植，若改选 Flutter 或对图表原生性能要求极致）。

### 4.2 后端

- **框架**：FastAPI（借 tickflow 的成熟结构）。
- **数据管道**：APScheduler 定时调度 + 数据源插件化（借 tickflow 插件架构 + easy-stock 多源聚合）。
- **计算**：Polars（指标流水线，借 tickflow）。
- **实时**：WebSocket 推送（行情/分时/异动）。

### 4.3 存储

| 层 | 选型 | 说明 |
|---|---|---|
| 历史行情 | **Parquet + DuckDB**（借 tickflow） | 日/分钟 K，列存压缩，DuckDB 秒查；按市场+周期分目录 |
| 实时/分时 | **Redis** | 当日分时缓存、最新快照、异动计算 |
| 用户数据 | PostgreSQL（或 SQLite 起步） | 账号、自选股、收藏、设置 |
| 文件缓存 | 本地磁盘 | 复权因子、题材映射等静态表 |

> 规模化（用户量大后）：历史行情迁 **ClickHouse/TimescaleDB**；DuckDB/Parquet 在 MVP 阶段完全够用且零运维。

## 6. 数据方案（详细）

### 6.1 数据源分层

| 层 | 源 | 责任 | 免费 |
|---|---|---|---|
| 日 K + 复权因子 | 东财 / 腾讯 / baostock | 全量 2010 至今 | ✅ |
| 5/15/30/60 分钟 | baostock（主）+ 东财（补近端） | 全量回填 | ✅ |
| 1 分钟 | 东财（近端）+ 付费源（预留） | 近端真实 + 远端付费 | ⚠️ |
| 当日分时 | 腾讯 `qt.gtimg.cn` / 东财 push2 | 实时 | ✅ |
| 历史分时 | 1 分钟 K 聚合（自构造）+ 东财 trends2 近端 | 降级 | ⚠️ |
| 题材/涨停/连板/龙虎榜/资金流 | 东财 / 同花顺 / 开盘啦 | 近实时 | ⚠️ 部分需 token |

### 6.2 管道设计（借 tickflow 思路）
1. **全量回填**（一次性）：日线 → 60/30/15/5 分钟逐频段回填，baostock 逐股逐日拉取（全市场首次回填预计数天，用任务队列 + 断点续传 + 幂等落盘）。
2. **增量同步**：
   - 盘中：免费源轮询快照 + 分时（秒/分钟级），写入 Redis，收盘后落 Parquet。
   - 盘后：日 K 增量 + 分钟 K 增量 + 复权因子更新 + 题材/涨停/龙虎榜快照落库。
3. **数据源状态与降级**（借 easy-stock）：每个数据点记录 `source + fetch_time + latency + degraded`，单源挂掉自动切备用源。

### 6.3 复权处理（借 tickflow）
- 独立 `adj_factor` 因子表（baostock/东财），原始价 + 因子自行算前/后复权，可审计、可回溯。

### 6.4 分时的构造
- **当日分时**：直接取实时 1 分钟/快照（腾讯/东财），约 240 点，含均价线与成交量。
- **历史分时**：优先 1 分钟 K 聚合出 240 点；1 分钟缺失的早年用 5 分钟 K 插值近似（明确标注「近似」）。

## 7. 数据模型（核心表）

```
symbols       标的元数据：code, market(SH/SZ/BJ), name, list_date, industry, concept[]
daily_bar     日 K：date, open, high, low, close, volume, amount, turnover, adj
minute_bar    分钟 K：ts, period(1/5/15/30/60), open, high, low, close, volume, amount
timeshare     分时：date, ts, price, avg_price, volume（当日实时存 Redis，历史落 Parquet）
adj_factor    复权因子：date, factor
concept_map   题材/概念 → 成分股映射
limit_up      涨停池 / 连板梯队快照
capital_flow  资金流（主力/散户、龙虎榜）
```

## 8. API 设计（REST + WebSocket）

**REST（历史/静态）**
- `GET /kline/{symbol}?period=daily|5m|15m|30m|60m|1m&adjust=前复权&start=&end=`
- `GET /timeshare/{symbol}?date=`（历史分时）
- `GET /snapshot?symbols=`（实时快照批量）
- `GET /concept/{id}`、`GET /limit-up?date=`、`GET /capital-flow/{symbol}`
- `GET /regime`（情绪周期）、`GET /ladder`（连板梯队）

**WebSocket（实时）**
- `sub:quote:{symbols}` → 实时快照推送
- `sub:timeshare:{symbol}` → 分时增量
- `sub:alert:{symbols}` → 异动推送

## 9. 界面设计（对标开盘啦）

### 9.1 信息架构（Tab 结构）
1. **首页（大盘）**：三大指数 + 涨跌家数分布 + 领涨/领跌板块 + 题材热力 + 异动事件流。
2. **行情**：全部股票列表（涨幅/成交额/换手/量比排序）+ 自选。
3. **个股**：分时图（当日/五日切换）↔ 日/周/月/60/30/15/5/1 分钟 K 线、盘口五档、资金流、题材标签、公告。
4. **题材/情绪**：题材梯队、连板梯队、情绪周期曲线、涨停复盘（这是开盘啦的灵魂，也是 easy-stock 已实现的领域模型）。
5. **我的**：自选管理、提醒设置、数据源状态。

### 9.2 视觉规范（DESIGN.md 思路，参考 awesome-design-md）
- **主题**：深色看盘（默认），支持浅色；红涨绿跌（A 股习惯）。
- **配色 tokens**：`--bg`（深底 `#0D1117` 系）、`--card`、`--up`（`#E64C3C` 红涨）、`--down`（`#2E9E5B` 绿跌）、`--accent`（品牌色）、`--muted`。
- **字体**：数字用等宽字体（价格跳动对齐），层级清晰。
- **组件**：卡片式行情列表、K 线画布（klinecharts）、可拖拽分时缩放、五档盘口、题材标签 chip。
- **交互**：个股页分时/K 线左右滑切换周期、长按十字光标、下拉刷新自选。

## 11. 风险与合规清单

1. **数据授权**：商用必须买数据源授权（立项预算项），免费源仅限学习研究。
2. **1 分钟/历史分时缺口**：免费源无法覆盖 2010 至今，MVP 降级 + 预留付费插件。
3. **监管**：不荐股、不预测、AI 结论加免责；行情展示相对安全。
4. **鸿蒙图表渲染**：klinecharts 走 renderjs/webview 承载，需真机验证性能；备选 ArkUI canvas 重绘。
5. **免费源稳定性**：接口会变/限流，必须做多源降级 + 状态监控（借 easy-stock 思路）。

## 12. 待确认（立项前需要你拍板）

1. **商业化 or 自用学习？** → 决定数据源是免费还是付费（最大成本项）。
2. **1 分钟与历史分时的精度要求**：可接受「近端真实 + 远端近似」还是必须付费全量？
3. **鸿蒙是 NEXT（纯血）还是兼容旧鸿蒙？** → NEXT 建议 uni-app x；若也要覆盖旧鸿蒙（APK 兼容层）则 Flutter/RN 亦可。
4. **团队/预算**：一人 PM + 少量前端，还是可招 3 端工程师？
5. **是否要小程序/Web 版**：uni-app x 一套代码顺手出，几乎零成本。
